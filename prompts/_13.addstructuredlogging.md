In apps/backend add request validation and one error format. Do not add any feature routes.

- A ZodValidationPipe (written by hand, no extra library) used as
  @Body(new ZodValidationPipe(schema)), returning the parsed (transformed) value.
- An AppException base class with a machine-readable code, an HTTP status, a message and
  optional details.
- A global exception filter that turns everything into:
  { statusCode, error, message, details?, path, timestamp }
  - zod failure → 400, error 'VALIDATION_FAILED', details [{ path, message }]
  - AppException → its own status/code
  - Nest HttpException → its status, error from its name
  - anything else → 500 'INTERNAL_ERROR' with a generic message; never leak the stack or
    the original message; log the real error.
    e2e tests using a controller registered only inside the test module: valid body passes,
    invalid body gives VALIDATION_FAILED with details, a thrown AppException keeps its code,
    a thrown plain Error gives a generic 500.

In apps/backend add structured logging with nestjs-pino so Nest's Logger and Fastify's
request logs share one pino logger.

- Request id: use the incoming x-request-id header if present (max 64 chars, safe
  characters only), otherwise generate a UUID; return it in the x-request-id response
  header and add requestId to the error format from the previous step.
- LOG_LEVEL in the zod env schema (default info; debug in development). Pretty output
  only in development; JSON otherwise.
- Redact the authorization and cookie headers.
  e2e tests: response has x-request-id, an incoming one is echoed back, error responses
  include requestId.
