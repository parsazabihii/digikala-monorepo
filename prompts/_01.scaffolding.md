You are a senior/staff engineer. Set up a **production-ready Turborepo monorepo from scratch called digikala** with first-class DX. It has three apps:

| App             | Stack                            | Dev port |
| --------------- | -------------------------------- | -------- |
| `apps/frontend` | Next.js (App Router, TypeScript) | 3000     |
| `apps/admin`    | React + Vite (TypeScript)        | 5173     |
| `apps/backend`  | NestJS (TypeScript)              | 4000     |

## Scope (read carefully)

- **This task is infrastructure and configuration only.** Create each app with its **official scaffolding CLI** and do NOT write any application code: no features, modules, pages, components, env-validation code or business logic.
- The only edits allowed in scaffolded source files are the minimal ones needed for the monorepo to work. For example: change the backend's default port in `main.ts` to 4000, or make a small fix if the shared strict config flags scaffolded code.
- Out of scope: CI/CD, Docker, deployment, and any shared UI package. Frontend and admin have different component sets, so do NOT create `@repo/ui`.

## 0. Before you start

1. Read the Turborepo skill in `.claude/` fully and follow its conventions. If it conflicts with this prompt, the skill wins, and you tell me about the conflict.
2. Use the **latest stable versions** of everything as of today. Check with `pnpm view <pkg> version` and `<cli> --help`. Don't rely on memory for versions or CLI flags.
3. Show me a short plan first (final folder tree + key decisions), then wait for my approval.

## 1. Scaffolding

- Generate each app with its official CLI (`create-next-app`, `create-vite` with the react-ts template, `@nestjs/cli new`). Use flags for pnpm, TypeScript, no git init, and skip install.
- After scaffolding, clean up per-app artifacts that conflict with the monorepo: nested `.git` folders, nested lockfiles, and per-app Prettier/ESLint/tsconfig bases that the shared configs replace.
- Use package names `frontend`, `admin` and `backend` so `--filter` stays short.

## 2. Workspace root

- **pnpm workspaces**: `pnpm-workspace.yaml` (`apps/*`, `packages/*`), the `packageManager` field, `engines`, `.nvmrc` (current Node LTS), and `.npmrc`. With pnpm 10+, configure `onlyBuiltDependencies` correctly.
- `turbo.json` with correctly set up tasks:
  - `build`: `dependsOn: ["^build"]` and accurate `outputs` per app (`.next/**` excluding `.next/cache/**`, `dist/**`).
  - `dev`: `persistent: true`, `cache: false`.
  - `lint`, `typecheck`, `test`, `clean`, `format`: with sensible `inputs`/`dependsOn`.
  - Declare `env`/`globalEnv`/`globalDependencies` (e.g. `.env*`) so the cache is never stale.
- Root scripts: `dev`, `build`, `start`, `lint`, `lint:fix`, `format`, `format:check`, `typecheck`, `test`, `clean`, plus `dev:frontend`, `dev:admin` and `dev:backend` via `--filter`.
- Every app must have the same script names (`dev`, `build`, `start`, `lint`, `typecheck`, `test`, `clean`) so turbo can orchestrate them all the same way.

## 3. Shared config packages (`packages/`, scope `@repo/*`)

These are config-only packages, with no runtime code.

- **`@repo/typescript-config`**: a strict `base.json` (`strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `verbatimModuleSyntax` where compatible, etc.) plus `nextjs.json`, `vite-react.json` and `nestjs.json`. NestJS needs decorators (`experimentalDecorators`, `emitDecoratorMetadata`) and the module/target settings compatible with Nest's CommonJS build. Each app's tsconfig extends the right preset.
- **`@repo/eslint-config`**: ESLint **flat config**, with presets `base`, `next`, `react-vite` and `nest`. Include typescript-eslint (type-aware), React Hooks and React Refresh rules where relevant, Next's official plugin for frontend, `eslint-plugin-turbo`, import ordering, and `eslint-config-prettier` so ESLint and Prettier never fight. Every app's `eslint.config.*` imports its preset. Note: check whether the current Next.js version still ships `next lint`. If it doesn't, run ESLint directly.
- **Prettier**: a single root config plus `.prettierignore`, used by all workspaces.

## 4. DX & quality gates

- Husky + lint-staged (format and lint only staged files), commitlint with Conventional Commits.
- Keep the testing setup each CLI ships (Jest for Nest, etc.) and make sure `pnpm test` runs through turbo. Apps without tests must exit successfully, not fail.
- `.vscode/settings.json` (format on save, ESLint flat config, workspace TypeScript SDK) and `.vscode/extensions.json` (recommended extensions).
- `.editorconfig`, a complete root `.gitignore` (`node_modules`, `.turbo`, `.next`, `dist`, `coverage`, `.env*` except `.env.example`, OS/IDE files).
- Each app gets a `.env.example` containing only what's needed to boot (e.g. `PORT`). Don't add env-validation code.
- Pin the dev ports from the table above in config (Next script flag, `vite.config` server port, Nest port) so they never collide.

## 5. Documentation

- Root `README.md` covering: the folder tree, prerequisites (Node, pnpm, corepack), quick start (`pnpm install && pnpm dev`), a table of scripts with what each does, apps and ports, how to add a new app or package, and how the shared configs work.
- `CLAUDE.md` with the repo conventions for future AI sessions.

## 6. Definition of done

Verify each item yourself by running the command. Don't assume.

1. `pnpm install` finishes cleanly with no peer-dependency warnings you could have avoided.
2. `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` all pass with **zero errors and zero warnings**.
3. Run `pnpm build` a second time. It must report **FULL TURBO** (every task cached).
4. `pnpm dev` starts **all three apps at once**. Confirm each one responds over HTTP: `curl` ports 3000, 5173 and 4000. Then stop the processes.
5. A test commit with a bad message is rejected by commitlint, and lint-staged runs on staged files.

Finally, give me a summary: the folder tree, every important decision and trade-off, and the suggested next steps.
