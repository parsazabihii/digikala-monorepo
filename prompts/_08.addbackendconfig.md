Add configuration to apps/backend with @nestjs/config.

- An env schema written in zod: NODE_ENV (development | production, default
  development), HOST (default 0.0.0.0), PORT (coerced number, default 4000).
- ConfigModule is global and validates with that schema at startup. On invalid env the
  app must refuse to start and print every invalid variable in a readable list.
- Typed access: inject ConfigService<Env, true> (or a small typed wrapper) so
  config.get('PORT') is typed. No process.env anywhere outside the schema.
- main.ts reads HOST and PORT from config.
- Commit .env.example with every variable; make sure .env is gitignored.
  Tests: valid env parses with defaults, invalid PORT fails with a clear message.
